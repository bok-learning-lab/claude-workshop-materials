# plan.md

> **In one line:** `plan.md` is a markdown file you write *before* doing any
> real work in a project — a deliberate plan that Claude can read, you can
> edit, and the rest of the session can refer back to.

## In plain terms

The default move when you open Claude Code in a new project is to start asking
for things. The recommended move is one step earlier: ask Claude to help you
write a **plan** for the project, save it as `plan.md`, and *then* start doing
the work.

`plan.md` is not a built-in Claude Code feature. It is a convention: a markdown
file at the root of your project that captures, in your own words, what you're
trying to build, in what order, with which constraints. A useful plan answers
roughly:

- What is this project? (Two sentences.)
- What are the inputs? What are the desired outputs?
- What's the rough sequence of steps? What's "done" look like?
- What's deliberately *not* in scope?

You can hand-write it. You can ask Claude to draft it from a few sentences of
context. Either way, the value comes from making the plan *visible* to both
you and to Claude across the session — and being willing to revise it as the
work surfaces new constraints.

## Why it matters in this workshop

`plan.md` is the cleanest expression of the workshop's central discipline:
**externalize the thinking**. The same reasons it matters to write before you
build apply equally to faculty work and software work. Plans you keep in your
head get muddled; plans on paper get *better* under revision; plans Claude can
read are plans Claude can stay aligned with.

It also answers the most common faculty version of "where do I start?" — start
by writing what you're trying to do, and let that doc shape the project that
follows.
